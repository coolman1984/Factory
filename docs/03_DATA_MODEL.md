# 🗂️ تنظيم البيانات والعقود

## ١. مجموعات البيانات

| المجموعة | أمثلة | قواعد الحفظ |
|---|---|---|
| كتالوجات | أصناف وقوالب ووصفات ومهارات | إصدار معلوم؛ التعديل لا يغير تشغيلًا سابقًا |
| تعريف المصنع | مواقع ومنافذ وشبكات وسياسات | نسخة معتمدة ونسخ تجارب |
| حالة التشغيل | رصيد وحجوزات وحمولات وطوابير | كاتب واحد وانتقالات متسقة |
| الأحداث | استلام وبدء وانتهاء ونقل وفحص | ترتيب ثابت؛ تصحيح بحدث جديد |
| المشاهدات الخارجية | قراءة حساس أو مسح باركود | مصدر وتوقيت وجودة ومعرف لمنع التكرار |
| مخرجات التجارب | مؤشرات ومقارنات وقياسات | مرتبطة بإعدادات التجربة وإصدار المحرك |

صيغة تبادل نصية مناسبة للتعريف والأمثلة، وقاعدة بيانات مناسبة للاستعلام والتاريخ عند التنفيذ. لا يعاد كتابة ملف ضخم مع كل إطار.

## ٢. الهوية والعلاقات

| الحقل المقترح | المعنى |
|---|---|
| `entity_id` | هوية ثابتة لا تعتمد على الاسم أو الموضع |
| `prefab_id` / `prefab_version` | مرجع قالب بإصدار |
| `org_parent_id` | التبعية الإدارية |
| `spatial_parent_id` | الأب المكاني للتركيب الثابت |
| `container_id` | الحاضن المادي الحالي للمادة أو وحدة المناولة |
| `assignment_id` | التكليف التشغيلي الحالي |
| `attachment_id` | ارتباط حركة مؤقت بمورد آخر |
| `revision` | إصدار لمنع الكتابة على حالة قديمة |

يمكن وجود علاقات إدارة متعددة في نموذج مؤسسي موسع، لكن مصدر المسؤولية الأساسي محدد. الأب المكاني الواحد لا يشكل دورة. الحاضن المادي لا يحتوي نفسه ولا يكون العنصر في حاضنين في الوقت نفسه.

## ٣. وحدات وإحداثيات موحدة

- وحدات التعريف المقترحة: المتر، والثانية، والكيلوجرام، والدرجة للزوايا البشرية المقروءة.
- المحوران الأول والثاني على الأرض، والثالث رأسي إلى أعلى، بنظام يميني. نقطة الأصل مثبتة في مخطط الموقع.
- موضع الجسم يشير إلى منتصف قاعدته، ما لم يعلن قالب محدد مرجعًا مختلفًا مع تحويل واضح.
- مصفوفة الموقع العالمي ناتج تركيب تحويلات الأسلاف ثم التحويل المحلي، بما يشمل الدوران.
- إعادة إلحاق عنصر بأب مختلف تحتاج اختيارًا صريحًا: الحفاظ على موقعه العالمي أو إعادة وضعه محليًا.
- شبكة الالتقاط أداة تحرير فقط؛ يمكن اختيار خطوة دقيقة أو تعطيلها. ليست دقة المحاكاة ولا حدًا لقياسات المصنع.
- أي محرك رسم يستخدم محورًا رأسيًا مختلفًا يعالج ذلك في موائم العرض؛ لا يغير تعريف المصنع.

```text
world_transform = parent_world_transform × local_transform
new_local_transform = inverse(new_parent_world_transform) × old_world_transform
```

## ٤. المنافذ

كل منفذ له معرف، وعنصر مالك، وموضع واتجاه محليان، ودور، وشروط توافق، ومساحة اقتراب، وسعة إشغال، وزمن تحميل أو تفريغ.

الأدوار: إدخال مادة، إخراج مادة، وقوف وسيلة نقل، مكان عامل، وصلة سير، وصلة خدمات. القرب الهندسي وحده لا ينشئ اتصال تدفق معتمدًا.

المراجع تستخدم معرف المنفذ. الموضع العالمي مشتق؛ الطريق مخبأ مشتق من إصدار التخطيط، لا حقيقة ثابتة داخل تعريف المهمة.

## ٥. المواد والتتبع

| نوع التتبع | أمثلة | وحدة السجل |
|---|---|---|
| فردي | جهاز نهائي، بوردة عند الحاجة | سيريال |
| دفعات | إنتاج حقن أو فوم، دفعة خام | دفعة وكمية |
| كمي | مسامير أو حبيبات | صنف وموقع ووحدة قياس |
| وحدات مناولة | صينية أو صندوق أو بالته | هوية ومحتويات |

تحويل الكيلوجرام إلى قطع يحدث بوصفة ومقادير وعائد وهالك، وليس بمجرد إعادة تسمية الصنف. الصنف الخام لا يساوي الصنف بعد التصنيع، حتى إن تشابه الشكل المرئي.

لا تجمع سعة مخزن بالقطع مع مخزون بالكيلوجرام. قدرة الموقع تقاس حسب نوعه: خانات، بالته، حجم، وزن، أو قيود متعددة معًا. الإشغال المحجوز يُحسب أيضًا.

## ٦. حركة المخزون

```text
Transfer: transfer_id, source_location_id, destination_location_id,
          item_id, quantity, unit, lot_or_serials, handling_unit_id
Reservation: reservation_id, demand_id, stock_refs, quantity, expires_at, state
InventoryEvent: event_id, transfer_id, kind, source, destination, quantity, unit
```

الحجز لا ينقل المادة فعليًا. التحميل ينقل العهدة إلى وسيلة النقل أو وحدة المناولة. التفريغ ينقلها إلى الوجهة. إلغاء المهمة يحرر الحجوزات التي لم تنفذ فقط، ويترك الحمولة الفعلية في مكانها مع مهمة معالجة.

الكمية المتاحة للصرف = الرصيد المقبول − الحجوزات النشطة. المواد المرفوضة أو المحجوزة للجودة لا تدخل الرصيد المقبول. المواد في الطريق تُحسب مرة واحدة وفق معرف الشحنة أو التحويل.

التصنيع يسجل استهلاك خامات وإنتاج مخرجات وهالكًا أو منتجات جانبية بوحداتها؛ لا يستخدم تحويل نقل لتغيير نوع مادة.

## ٧. حالات موارد وأعمال

| الكيان | حالات مقترحة |
|---|---|
| المحطة | متاحة، تجهيز، تشغيل، نقص خامة، تعذر تفريغ، عطل، صيانة، خارج وردية |
| مهمة النقل | طلب، حجز، توجه للاستلام، تحميل، نقل، انتظار تفريغ، تفريغ، مكتملة، متعثرة، ملغاة |
| العامل | متاح، انتقال، تشغيل، مناولة، استراحة، غير متاح |
| المادة | مقبولة، تحت التشغيل، حجر جودة، إصلاح، مرفوضة، مستهلكة، مشحونة |

كل انتقال يحدد شروطًا وأحداثًا وآثارًا. لا تحفظ نسب تقدم ومخرجات نهائية متناقضة. التقدم المرئي مشتق من الزمن وحالة العملية.

## ٨. مخطط ملفات البيانات المقترح

```text
catalogs: items, prefabs, recipes, skills, asset_manifests
blueprints: entities, ports, process_routes, navigation, utilities, policies
runtime: stock, reservations, jobs, resource_states, clock, scheduled_events
history: events, snapshots, observations, scenario_results
```

هذه أقسام منطقية، وليست فرضًا لإنشاء خدمة مستقلة أو ملف مستقل لكل قسم.

## ٩. مستوى اكتمال العينة

عينة المستودع ومخططها البنيوي يثبتان شكل تعريف قابل للقراءة ويحتوي على كل القطاعات الأساسية. لا يحتويان حالة تشغيل كاملة أو كل العقود المستقبلية. القيود بين السجلات — مثل صحة المراجع وتوافق الوحدات — تحتاج فحصًا دلاليًا بالإضافة إلى المخطط البنيوي.

أي تغيير في هذا العقد يحتاج تحديث المخطط والعينة وشرح ترحيل الملفات المتأثرة، قبل استخدامه في تنفيذ فعلي.
